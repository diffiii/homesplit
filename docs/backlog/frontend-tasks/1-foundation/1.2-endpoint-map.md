# 1.2 Add an endpoint map to the contracts

**Labels:** `backend`, `frontend` · **Epic:** [1 Foundation](1.0-epic.md) · **Depends on:** none

**Goal:** Every application route is described once, as data, so clients and mocks are typed from it instead of copying paths from the decision record.

**Scope:** An endpoint map in `@homesplit/contracts` with one entry per `/api` route: method, path template, params, query, body, success status, and response schemas. Better Auth's `/api/auth/*` endpoints aren't included; the frontend uses Better Auth's client for them.

**Acceptance criteria:**

- [ ] The map covers every route in the [decision record's route table](../../../decisions.md#routes), with the contract schemas each route already uses. Routes whose contracts don't exist yet are added by the tasks that create them.
- [ ] Path templates use the contract param names (`:householdId`, `:expenseId`, ...), and a helper builds a path from typed params.
- [ ] Query schemas keep their codecs, so a client can encode typed values into a URL and the backend decodes the same strings.
- [ ] Entries are plain data plus Zod schemas, with no HTTP library, so the backend, the web app, and the mocks can all import them.
- [ ] A backend test fails when a registered `/api` route has no map entry or its method and path differ from it.
- [ ] The backlog's proposed rule is adopted: backend tasks that add or change a route update the map in the same PR.

**References:** [contracts](../../../../packages/contracts/src), [decision record: API conventions](../../../decisions.md#api-conventions)
