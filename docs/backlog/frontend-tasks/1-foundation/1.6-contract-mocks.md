# 1.6 Mock the API from the contracts

**Epic:** [1 Foundation](1.0-epic.md) · **Depends on:** [1.2](1.2-endpoint-map.md), [1.5](1.5-api-layer.md)

**Goal:** Frontend tasks can be built and tested before their backend tasks are done, against mocks that behave like the real API where the UI depends on it.

**Scope:** MSW handlers for the browser and for tests, an in-memory store with data factories, and switchable scenarios.

**Acceptance criteria:**

- [ ] Handlers are registered from the endpoint map, validate requests with the same schemas, and return contract-valid responses. A handler for a route without an implementation fails loudly.
- [ ] The mocks follow the decision-record rules the UI relies on: 404 for non-members, `MODULE_DISABLED` for writes in a disabled module, `FORBIDDEN` by role, pagination shape and ordering, and idempotent actions.
- [ ] The Better Auth endpoints the app uses (session, sign-in and sign-up, organizations, members, invitations) are mocked.
- [ ] Factories build two households, every role, a departed member, a disabled module, and multiple currencies. Scenarios can be switched in development without code changes.
- [ ] Mocks are enabled by an environment flag and never included in production builds.

**References:** [MSW](https://mswjs.io/), [decision record](../../../decisions.md)
