# 1.4 Serve the backend behind the frontend origin and agree on email links

**Labels:** `backend`, `frontend` · **Epic:** [1 Foundation](1.0-epic.md) · **Depends on:** none · **Related:** [#28](https://github.com/diffiii/homesplit/issues/28), [#59](https://github.com/diffiii/homesplit/issues/59)

**Goal:** Better Auth works through the frontend's `/api/*` rewrite, and every email the backend sends links to a page the frontend has.

**Scope:** Better Auth and Nest configuration for requests proxied from the frontend origin, a shared `FRONTEND_URL`, and a decision-record entry for frontend paths used in emails.

**Acceptance criteria:**

- [ ] `BETTER_AUTH_URL` is the public frontend origin, so URLs Better Auth builds go through the frontend. `trustedOrigins` contains the frontend origins for each environment, including Vercel preview URLs.
- [ ] Session cookies are set without a `Domain` attribute, `Secure` outside local development, and `SameSite=Lax`, so they belong to the frontend origin. CORS stays disabled, because the browser never calls the API origin directly.
- [ ] Rate limits and session IP addresses use the client's address from the forwarding headers, not the proxy's.
- [ ] `FRONTEND_URL` is a documented environment variable, shared with [#28](https://github.com/diffiii/homesplit/issues/28) and [#59](https://github.com/diffiii/homesplit/issues/59).
- [ ] The decision record lists the frontend paths emails link to: `/invitations/:invitationId`, `/verify-email`, and `/reset-password`, and how each one returns the user to where they were going after signing in. This goes in its own PR.
- [ ] A test signs up, signs in, and calls an `/api` route through a proxy that mimics the rewrite.
