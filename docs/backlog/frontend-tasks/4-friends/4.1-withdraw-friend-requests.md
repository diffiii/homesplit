# 4.1 Let senders withdraw friend requests

**Labels:** `backend`, `frontend` · **Epic:** [4 Friends](4.0-epic.md) · **Depends on:** [#31](https://github.com/diffiii/homesplit/issues/31), [#32](https://github.com/diffiii/homesplit/issues/32)

**Goal:** A user can take back a friend request they sent by mistake.

**Scope:** `DELETE /api/me/friend-requests/:requestId` for the sender, with its endpoint map entry and a decision-record update.

**Acceptance criteria:**

- [ ] Only the sender can withdraw a request. It answers 204 and deletes the request, so it disappears from the recipient's incoming list.
- [ ] A request that was already accepted, declined, or withdrawn answers 404, like the other friend-request actions. The recipient answers requests with accept and decline, not with this route.
- [ ] The decision record's route table and permissions matrix list the route, in its own PR.
- [ ] Tests cover the sender, the recipient, another user, and a repeated withdrawal.
