# 3.2 Build the household shell

**Epic:** [3 Households](3.0-epic.md) · **Depends on:** [3.1](3.1-household-list-create.md), [#27](https://github.com/diffiii/homesplit/issues/27)

**Goal:** Every screen under `/households/:householdId` knows the household, the caller's role, the members, and the enabled modules, and adapts to them.

**Scope:** The household layout, data loaded once for its pages, navigation by module, and permission helpers.

**Acceptance criteria:**

- [ ] The layout loads the household, its members, and `GET /features`, and shares them with every page without refetching per page.
- [ ] Navigation shows expenses, chores, and shopping. A disabled module stays reachable read-only, with a notice that an admin can turn it back on.
- [ ] Permission helpers implement the [decision record's matrix](../../../decisions.md#roles-and-permissions) from the caller's strongest role and resource fields (author, payer, payee), and every later task uses them.
- [ ] A helper marks any `UserSummary` that isn't a current member as departed.
- [ ] A 404 from any household route, or a household the user is no longer in, shows a not-found page with a way back to the switcher.

**References:** [household contracts](../../../../packages/contracts/src/features/households/index.ts), [decision record: disabled modules](../../../decisions.md#disabled-modules)
