# Epic 2: Households

**Backlog:** [Backend backlog](../../backend-backlog.md) · **Depends on:** [Epic 1](../1-foundation/1.0-epic.md)

**Goal:** Every household-scoped route can trust who the user is, which household they belong to, and which modules are enabled.

**Tasks:**

- [2.1 Enforce household membership and resource isolation](2.1-membership-isolation.md)
- [2.2 Implement household feature settings](2.2-feature-settings.md)
- [2.3 Send household invitations by email](2.3-email-invitations.md)

**Epic done when:**

- [ ] A shared guard rejects nonmembers and removed members on any household route.
- [ ] Module settings exist for every organization, and a shared check rejects mutations on disabled modules.
- [ ] Household invitations are delivered by email and can be accepted through the link.
- [ ] A two-household test fixture is available, and later epics use it to prove that IDs, references, lists, and mutations don't leak across households.
