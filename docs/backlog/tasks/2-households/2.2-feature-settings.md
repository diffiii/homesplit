# 2.2 Implement household feature settings

**Epic:** [2 Households](2.0-epic.md) · **Depends on:** [2.1](2.1-membership-isolation.md)

**Goal:** Each household can turn the expenses, chores, and shopping modules on and off, and every feature can check that state.

**Scope:** An organization-keyed settings table with its migration, GET/PATCH settings endpoints, and a shared enabled-module check. Better Auth's organization lifecycle endpoints are reused unless 1.1 requires a wrapper.

**Acceptance criteria:**

- [ ] Creating a household seeds its settings with all modules enabled, and a migration backfills existing organizations.
- [ ] Partial updates keep unspecified flags, and only the roles allowed by 1.1 can change settings.
- [ ] A shared check (guard or decorator) blocks mutations on disabled modules and still allows reads. Data survives disable followed by re-enable.
- [ ] Tests cover organization creation, invitation, and member-removal integration. Any change to generated auth tables (such as membership uniqueness) is called out with its migration impact.
