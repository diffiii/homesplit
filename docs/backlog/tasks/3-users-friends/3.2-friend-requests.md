# 3.2 Send and list friend requests

**Epic:** [3 Users and friends](3.0-epic.md) · **Depends on:** [3.1](3.1-profile-projections.md)

**Goal:** A user can send a friend request by email and see their incoming and sent requests.

**Scope:** Friendship and friend-request tables with their migration, a send-by-email endpoint, and incoming/sent list endpoints.

**Acceptance criteria:**

- [ ] The requester comes from the session. The recipient email is normalized, and the response for an unknown email follows the privacy decision from [1.1](../1-foundation/1.1-decisions-household-permissions-api.md). Successful responses contain a real `FriendUser`; any required contract change is agreed before implementation.
- [ ] Self requests and duplicate requests are rejected by both transaction-safe logic and database constraints. The behavior for crossed requests (A asks B while B asks A) is decided and implemented.
- [ ] Lists are unpaginated as contracted and show the other user from the viewer's perspective.
- [ ] HTTP tests cover validation, duplicates, and unknown recipients.
