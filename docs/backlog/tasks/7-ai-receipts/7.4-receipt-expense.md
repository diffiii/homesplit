# 7.4 Assign receipt items and create the expense

**Epic:** [7 AI and receipts](7.0-epic.md) · **Depends on:** [7.3](7.3-receipt-scanning.md), [7.2](7.2-category-suggestions.md), [4.3.2](../4-expenses/4.3-attachments/4.3.2-expense-attachments.md)

**Goal:** Members assign each receipt item to one or more people, and confirming the receipt creates an expense with exact per-person splits.

**Scope:** A receipt-item assignment table with its migration, endpoints to set assignments, a preview of per-person amounts, and a confirm endpoint that creates the expense, links the receipt photo as an attachment, and marks the receipt as confirmed in one transaction.

**Assignment model:** every assignment is a number of shares of one item. Assigning an item to one person gives that person 1 share. Assigning it to several people with 1 share each splits it equally. For items with a quantity above 1, the client can set a number of units per person, which is stored as that person's shares (for example 2 of 3 beers for A and 1 for B). Weighed items only use shares.

**Calculation:** each item's cost after its line discount is split between its assignees in proportion to their shares, and receipt-level discounts are spread over items in proportion to their cost. Per-person amounts are summed without rounding and rounded once at the end with the 4.1.2 engine's remainder rule, so the splits add up exactly to the receipt total. The expense is created with the `exact` allocation method.

**Acceptance criteria:**

- [ ] Assignees must be current members of the receipt's household, and shares are positive.
- [ ] The preview returns each person's amount, the unassigned amount, and the difference from the receipt total. Confirming is rejected while any item is unassigned or the item sum doesn't match the total.
- [ ] Confirming takes the payer (defaulting to the uploader), the expense name and date (defaulting to the merchant and receipt date), and the category (defaulting to the 7.2 suggestion). It goes through the same validation as manual expense creation.
- [ ] The receipt keeps its items and assignments, and the expense links back to the receipt. The behavior when the expense's financial data is later edited (for example the receipt is unlinked) is documented and tested.
- [ ] Confirming twice, or confirming a receipt that is still processing, is rejected, and a failure at any step rolls everything back.
- [ ] Tests cover the example below, uneven remainders, receipt-level discounts, weighed items, unassigned items, and rollback.

Example: beer 3 × 4.99 = 14.97 (A 2 units, B 1 unit) and pizza 30.00 (A, B, and C equally) give A 19.98, B 14.99, and C 10.00, for a total of 44.97.

**Client screen (reference for the contract):** a list of items showing the name and quantity × price = total, with a member avatar row under each item. Tapping an avatar toggles an equal share, and a per-person unit stepper appears for items with a quantity above 1, along with a counter such as "2/3 assigned". Members can select several items and assign them in one step, or use "split everything equally". A footer shows each person's live total, the unassigned amount, and whether the item sum matches the receipt total. It also includes the payer and category pickers and the confirm button. Items stay editable on this screen to fix extraction errors.
