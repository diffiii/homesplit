# 7.1 Integrate an AI provider

**Epic:** [7 AI and receipts](7.0-epic.md) · **Depends on:** [2.2](../2-households/2.2-feature-settings.md)

**Goal:** Features call one internal AI interface that returns validated, structured results, and households control whether their data is sent to an AI provider.

**Scope:** Record the provider and model choice, a provider-independent interface for text and image prompts with structured output, a production adapter, a deterministic fake adapter for tests, and an `ai` household module flag. Before implementing, record the privacy policy for sending receipt images and expense text to the provider.

**Acceptance criteria:**

- [ ] Every AI response is validated against a Zod schema before it is used, and invalid or partial output is reported as a failure instead of being passed on.
- [ ] Provider credentials, model names, timeouts, and retries come from environment config. A missing configuration disables AI features instead of breaking startup.
- [ ] `ai` is added to the feature catalog and the 2.2 settings, and it defaults to disabled so that a household opts in before any data leaves HomeSplit.
- [ ] Usage is limited per household (for example requests per day), and exceeding the limit returns a documented error.
- [ ] Tests use the fake adapter and cover schema validation failures, timeouts, the disabled module, and the usage limit. No test calls the real provider.
