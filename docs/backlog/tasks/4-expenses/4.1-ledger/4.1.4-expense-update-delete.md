# 4.1.4 Implement expense update and delete with atomic financial replacement

**Epic:** [4.1 Ledger](4.1.0-epic.md) · **Depends on:** [4.1.3](4.1.3-expense-persistence-create-read.md)

**Goal:** An edit never leaves an expense in a half-updated financial state.

**Scope:** PATCH and DELETE endpoints for expenses.

**Acceptance criteria:**

- [ ] When `financial` is supplied, the total, payers, allocation input, and splits are replaced together in one transaction. A descriptive-only patch leaves all financial state untouched.
- [ ] Delete removes the expense and its child rows atomically and leaves settlement payments untouched.
- [ ] Mutations enforce the 1.1 roles and the disabled-module policy.
- [ ] Tests cover invalid financial replacement, rollback, concurrent replacement (per the policy documented here), and deleting a referenced category per 4.1.1.
