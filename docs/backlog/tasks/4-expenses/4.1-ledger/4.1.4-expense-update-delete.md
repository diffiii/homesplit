# 4.1.4 Implement expense update and delete with atomic financial replacement

**Epic:** [4.1 Ledger](4.1.0-epic.md) · **Depends on:** [4.1.3](4.1.3-expense-persistence-create-read.md)

**Goal:** An edit never leaves an expense in a half-updated financial state.

**Scope:** PATCH and DELETE endpoints for expenses.

**Acceptance criteria:**

- [ ] When `financial` is supplied, the total, payers, allocation input, and splits are replaced together in one transaction. A descriptive-only patch leaves all financial state untouched.
- [ ] Financial replacement applies the 1.1 historical-edit rules to departed users already on the expense and the eligibility rules for newly added payers or participants.
- [ ] Delete removes the expense and its child rows atomically. Task 4.2.2 verifies that expense deletion leaves recorded settlement payments untouched once both features exist.
- [ ] Mutations enforce the 1.1 roles and the disabled-module policy.
- [ ] The concurrent-update policy is chosen and documented here, including how overlapping financial replacements are handled. Any required contract change, such as a version field or ETag precondition, is proposed before implementation.
- [ ] Tests cover invalid financial replacement, rollback, overlapping financial replacements under the chosen policy, and correcting an expense after a payer or participant leaves under the 1.1 rules.
