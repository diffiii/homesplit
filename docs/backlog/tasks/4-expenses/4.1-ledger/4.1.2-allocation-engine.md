# 4.1.2 Implement the deterministic allocation engine

**Epic:** [4.1 Ledger](4.1.0-epic.md) · **Depends on:** none

**Goal:** The backend splits any total into per-user shares exactly and identically every time, without losing a minor unit to rounding.

**Scope:** A pure module with no HTTP or database code that implements the equal, percentage, shares, exact, and adjustment methods. Before implementing, record the supported currencies, minor-unit interpretation, and numeric limits.

**Acceptance criteria:**

- [ ] Supported currencies, numeric limits, and the database/API integer conversion policy are documented, and 4.1.3 and 4.2.1 reuse them.
- [ ] Outputs are integer minor units that add up exactly to the total, with no negative shares. Zero shares are allowed where valid.
- [ ] Inputs are validated: unique participants, a nonempty set, percentages summing to 10,000 basis points, and exact amounts matching the total. Adjustments are applied after the remainder is split equally, as contracted.
- [ ] Remainders are allocated by an explicit, stable tie-breaker, so reordered inputs produce identical results.
- [ ] Unit tests cover a one-minor-unit total, uneven division, all five methods, signed adjustments, zero shares, reordered inputs, and boundary values.
