# 4.2.2 Compute member balances per currency

**Epic:** [4.2 Settlements](4.2.0-epic.md) · **Depends on:** [4.1.4](../4.1-ledger/4.1.4-expense-update-delete.md), [4.2.1](4.2.1-payments.md)

**Goal:** Each member sees what they're owed or what they owe, separately for each currency.

**Scope:** An unpaginated balance endpoint computed from stored payers, splits, and payments, with no cache table.

**Acceptance criteria:**

- [ ] For each user and currency, balance = amount paid on expenses − allocated shares + payments sent − payments received. A positive balance means the user is owed money.
- [ ] Output is grouped by currency, and each group sums to zero. Ordering, inclusion of zero balances, and empty-household behavior are specified.
- [ ] Departed members are included according to 1.1.
- [ ] One response reads from a consistent snapshot, and aggregation avoids double counting through joins between child tables.
- [ ] Tests cover the [worked example](../../../backend-backlog.md#key-design-decisions), multiple payers, payers outside the allocation, multiple currencies, expense edit/delete, and repeated payments.
