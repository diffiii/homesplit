# 1.3 Integrate shared contracts with Nest validation and error handling

**Epic:** [1 Foundation](1.0-epic.md) · **Depends on:** [1.1](1.1-decisions-household-permissions-api.md)

**Goal:** Every application route validates input and returns output using the shared Zod schemas, and every failure uses one error shape.

**Scope:** Reusable pipes/decorators for params, bodies, and queries; a global exception filter; serialization helpers; and an `/api` prefix for application routes.

**Acceptance criteria:**

- [ ] UUID params, JSON bodies, and string query values are validated with the shared schemas and query decoders, never JavaScript truthiness. Pagination defaults are `page=1`, `pageSize=20`, maximum 100.
- [ ] A global exception filter maps validation, auth, not-found, and conflict errors to the `ApiError` envelope. Unexpected errors don't leak internals.
- [ ] Application routes live under `/api` and parse JSON, while Better Auth keeps working (bootstrap currently sets `bodyParser: false`).
- [ ] Responses serialize nullable fields, date-only strings, UTC datetimes, and safe integers as the contracts expect.
- [ ] HTTP tests cover valid and malformed requests and check representative responses against their schemas.
